# 二分答案 全套算法手册

> 实战前置：P2440 ✅ P1873 ✅ P1182 ✅ | P1163（浮点二分）待做
> 一句话定位：**二分 = 把"猜答案"从暴力枚举变成 O(logn) 次验证。**

---

## 〇、二分查找 vs 二分答案（先分清，别混）

| | 二分查找 | 二分答案 |
|---|---|---|
| 找什么 | 数组里**已经存在**的数（下标） | 一个**我们自己猜出来**的答案值 |
| 前提 | 数组有序 | 可行性**单调** |
| 核心 | 比较 a[mid] 和 target | check(mid) 判断 mid 可不可行 |
| 结束 | l == r（下标） | l == r（整数）或 r-l<eps（浮点） |

**关键区分**：二分查找的答案在数据里；二分答案的答案在**数学上存在但数据里没有**，要靠"验证"去逼近。

---

## 一、什么题用二分答案（判别三特征）

1. **问的是"最大/最小是多少"这样的一个数值**（每段多长、最大值多小、利率多少……），而不是"谁和谁"的关系题；
2. **直接算难、验证容易**：直接求出答案不好想，但**给你一个候选值 mid，"这个行不行"秒算**；
3. **可行性单调**：mid 越大，可行性要么一直变好、要么一直变差（见下节）。

> 三个全中 → 二分答案。中两个 → 大概率也是。
> 这是和其他算法（贪心/DP/图论）分流的**第一判断**。

---

## 二、单调性 —— 二分的命根子

可行/不可行的分布，**一定是一段"真"接一段"假"**，中间只有一条分界线。如果没有单调性，二分就是错的。

```
假假假假假 真真真真真 假假假假   ← 只有一条分界（具体形态看题目）
```

### 两种典型形态（记住它们，考场直接套）

**形态 A：mid 越大，可行性越差（真在前、假在后）**
> 最大化类题目，如 P2440 切木：mid（每段长度）越大 → 总段数越少 → 越难满足 ≥k。
> 要找 **最后一个真**。

```
mid:   1  2  3  4  5  6  7 ...
      真 真 真 真 假 假 假
                ↑ 最后一个真 = 答案
```

**形态 B：mid 越大，可行性越好（假在前、真在后）**
> 最小化类题目，如 P1182 数列分段：mid（每段和上限）越大 → 越容易装进 M 段。
> 要找 **第一个真**。

```
mid:   1  2  3  4  5  6  7 ...
      假 假 假 真 真 真 真
                ↑ 第一个真 = 答案
```

> 分析单调性的方法：**问自己"mid 变大，check 的判定结果怎么变"**，得到"变差"或"变好"，就知道方向了。

## 三、两大方向模板（整数二分，背熟）

> 全部建立在 `l` 是下界、`r` 是上界、答案一定在 `[l, r]` 内。

### 方向 A：最大化 → 找最后一个真（P2440 / P1873）

```cpp
bool check(ll mid){ /* mid 可行吗？*/ }

while(l < r){
    ll mid = (l + r + 1) / 2;   // ← 向上取整！防死循环
    if(check(mid)) l = mid;     // 可行 → 还能更大 → 往右收
    else r = mid - 1;           // 不可行 → 往左收
}
cout << l;
```

### 方向 B：最小化 → 找第一个真（P1182）

```cpp
bool check(ll mid){ /* mid 可行吗？*/ }

while(l < r){
    ll mid = (l + r) / 2;       // ← 向下取整
    if(check(mid)) r = mid;     // 可行 → 还能更小 → 往左收
    else l = mid + 1;           // 不可行 → 往右抬
}
cout << l;
```

### 记忆口诀（防止考场方向搞反）

| 特征 | 真值位置 | 真时怎么动 | mid 取整 |
|---|---|---|---|
| 找**最后一个**真（最大化） | 靠右 | `l = mid` | 向上 `+1` |
| 找**第一个**真（最小化） | 靠左 | `r = mid` | 向下 |

> 口诀：**"往右收就用 l=mid，且 mid 必须向上取整防卡死；往左收就用 r=mid，mid 向下取整。"**
> 配套记法：真时 `l=mid` → mid 若也等于 l 就死循环 → 所以 mid 要 **+1**；真时 `r=mid` → 无此风险 → 不加。

### 死循环陷阱（必考血泪）

方向 A 的 `l = mid`，**mid 必须向上取整**。反例：
```
l=5, r=6, mid=(5+6)/2=5 → check(5) 真 → l=mid=5 → 死循环！
```
如果 mid=(5+6+1)/2=6 → l=6 == r → 正常退出。**这条忘了，TLE 就来了。**

## 四、check() 函数设计（90% 的翻车在这里）

模板是死的，check 是活的。二分答案题**最容易错的是 check 写错，不是模板写错**。

### 模式 1：贪心验证（P2440 / P1182）

验证"给个上限/下限，最少/最多能怎样"——用一个贪心或计数解决。

```cpp
// P1182 模式：每段和 ≤ mid 时最少分几段（就是 P1181 的贪心）
bool check(ll mid){
    ll cnt = 1, cur = 0;
    for(auto x : a){
        if(x > mid) return false;   // 单个元素就超上限 → 直接判死
        if(cur + x <= mid) cur += x;
        else { cnt++; cur = x; }
    }
    return cnt <= m;                // 最少段数 ≤ M ⟺ 恰好 M 段可行
}
```

### 模式 2：直接模拟（P1163 银行贷款）

按题意从头到尾模拟一遍，看结果符号判断 mid 大小。

```cpp
// 猜月利率 mid，模拟 m 个月，剩余欠款符号决定 mid 大还是小
bool check(double mid){
    double debt = n;
    for(int i = 1; i <= m; i++) debt = debt * (1 + mid) - k;   // 先长息再还款
    return debt <= 0;    // 还清了 → mid 足够大（可行性好）
}
```

### check 设计口诀
> 先问：**"给我一个 mid，我凭什么判断它行不行？"** 答案是某个可快速计算的量（总段数、剩余欠款、总时间……）。这个量的符号/大小就是 check 的返回值。

## 五、边界设定

| 边界 | 怎么定 | 例子 |
|---|---|---|
| 下界 l | 答案的最小可能值 | P1182：`l = max(a[i])`（每个数必须单独装下）|
| 上界 r | 答案的最大可能值 | P1182：`r = sum(a[i])`（全部装一个袋子）|
| 浮点 l/r | `l=0`，`r` 给个安全的大数 | P1163：`r = 1` 或更大 |

> 下界设小、上界设大没关系（二分 O(logn) 不心疼），但**答案必须落在 [l,r] 内**，否则错。
> 极端保护：check 里对 mid 越界的情况显式 return false（如 `a[i] > mid`）。

## 六、浮点二分（P1163 新副本）

整数二分靠 `l==r` 退出，**浮点没法等相等**（浮点误差），靠**精度**退出：

```cpp
double l = 0, r = 1e9;              // 安全边界
while(r - l > eps){                  // eps：判据精度
    double mid = (l + r) / 2;
    if(check(mid)) r = mid;          // 方向看单调性
    else l = mid;
}
printf("%.1f%%\n", l * 100);        // 按题目格式输出
```

### eps 怎么选（关键）

| 题目要求保留 | eps 至少 | 原因 |
|---|---|---|
| 1 位小数 | 1e-4 以上（保险 1e-6） | 四舍五入在边界上不能抖 |
| 2 位小数 | 1e-6 | 同上 |

> 口诀：**保留 d 位小数 → eps 至少要 1e-(d+2)**。因为四舍五入是"误差 < 0.5×10^-d 就不抖"，eps 得比它再小两个量级。

### 浮点 vs 整数二分差异表

| | 整数二分 | 浮点二分 |
|---|---|---|
| 退出条件 | `while(l < r)` | `while(r - l > eps)` |
| 结束输出 | `l`（==r） | `l` 或 `(l+r)/2` |
| mid 取整 | 方向 A 要 `+1` | 不需要 |
| 输出格式 | 直接 cout | 注意小数位 + 百分号 |

## 七、踩坑清单（血泪合集，考前看一遍）

1. **死循环**：方向 A `l=mid` 时 mid 忘加 `+1` → TLE。
2. **方向搞反**：最大化/最小化分不清 → 用"找第几个真"判断，别硬背模板。
3. **check 算错**：90% 的翻车在这。写完整数边界、贪心方向、`a[i]>mid` 判死。
4. **恰好 M 段**：用"最少段数 ≤ M"验证——段数只能由**切**增多、不能由**并**减少（并会超上限），正数保证切永远安全。
5. **浮点 eps 太松**：四舍五入抖，答案差 0.1。eps 按 d+2 规则来。
6. **int 溢出**：`sum` 可达 10^14（10^5 个数 × 10^9），**用 long long**。
7. **输出格式**：百分号 `%`、保留小数位，`printf("%.1f%%")` 里 `%%` 才是字面百分号。
8. **二分查找乱用**：数组无序就别二分；答案不单调就别二分答案。

## 九、同类变式思考（进阶方向）

1. **二分 + 贪心**：答案二分，check 里套贪心（本周 P1182 就是）。
2. **二分 + 前缀和**：check 里用前缀和 O(1) 求区间和，把 O(n) 的 check 优化成 O(logn)。
3. **二分 + 排序**：check 里先排序再判定。
4. **实数域三分**：答案不是单调而是**单峰**（凸函数）时，用三分（进阶，暂不展开）。
5. **STL 的 lower_bound/upper_bound**：本质是"找第一个 ≥/第一个 > x"的二分查找，和二分答案的"找第一个真"思维相通。
