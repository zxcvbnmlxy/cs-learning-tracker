# P2679 子串 题解

> 2026-08-16 完成 | 字符串 DP + 滚动数组 | NOIP2015 D2T2（难度偏高，DP 设计的"四维状态"是核心）
> 一句话定位：**把 A 切成恰好 k 段（顺序不变、段不重叠），拼出 B，问方案数。**

---

## 一、题目在说什么

- 给两个字符串 A（长 n）、B（长 m），整数 k。
- 从 A 中取**恰好 k 个互不重叠的子串**，按在 A 中的**先后顺序**取出，拼接起来要**正好等于 B**。
- 问：有多少种取法（A 中每个位置最多被取一次）。

**样例**：A=`aabaab`，B=`aab`，k=1。
取 1 段 = 直接找 `aab` 作为 A 的子串：
`A[1..3]=aab`、`A[4..6]=aab` → 答案是 **2**。

> 关键理解：子串要按顺序拼，所以天然是一个"顺着 A 走、顺着 B 匹配"的过程 → 往 **DP** 上想。

---

## 二、DP 数组的含义（这题的钥匙）

```
f[i][j][t][0/1]
```

- `i`：用了 A 的前 i 个字符（A[1..i]）；
- `j`：已经拼出 B 的前 j 个字符（B[1..j]）；
- `t`：用了恰好 t 段子串；
- **`0/1`：A[i] 这一个字符，被用没用到？**

拆开讲这个 0/1，它是整题的灵魂：

| 值 | 含义 | 通俗说法 |
|---|---|---|
| `f[i][j][t][0]` | 考虑了 A 前 i 个字符，拼出 B 前 j 个，用了 t 段，**且第 i 个字符没被选中**（没进任何一段） | A[i] "闲置" |
| `f[i][j][t][1]` | 同样，**且第 i 个字符被选中，作为当前第 t 段的最后一个字符** | A[i] "服役" |

> 这个 0/1 是不是很像 01 背包的"拿/不拿"？对，**它就是把"每个字符的取用状态"单独拎出来做一维**——只有知道 A[i] 拿了没有，才知道它能不能"接"在上一段后面，还是得"新开一段"。

**答案**：`f[n][m][k][0] + f[n][m][k][1]`（A 全看完、B 全拼完、恰好 k 段，A[n] 拿不拿都行）。

---

## 三、转移方程：两种情况，讲透每一条

从 A[i-1] 走到 A[i]，B 和段数都只能"加"（j 和 t 只能从更小的过来）。

### 3.1 不选 A[i] → `f[i][j][t][0]`

A[i] 没用上，那它和 B 的字符**相不相等，完全没关系**。

B 的前 j 个、k 段，都是由 A 的前 i-1 个字符拼出来的——A[i] 只是路过。

所以：

```
f[i][j][t][0] = f[i-1][j][t][0] + f[i-1][j][t][1]
                 （A[i-1]没拿）    （A[i-1]拿了）
```

**无条件计算**，不需要任何 `A[i]==B[j]` 的判断。

> ⚠️ **这是第一个坑，重点看第四节**：很多人把这个转移写进 `if(A[i]==B[j])` 里，直接错。

### 3.2 选 A[i] → `f[i][j][t][1]`

选了 A[i]，它就必须等于 B[j]（它要作为当前段的字符跟 B[j] 对上）：

```
只当 A[i] == B[j] 时：
f[i][j][t][1] = f[i-1][j-1][t][1]   （延续：A[i-1] 也在第 t 段，A[i] 接在后面）
              + f[i-1][j-1][t-1][0]  （新开一段：A[i-1] 没拿，A[i] 独自开第 t 段）
              + f[i-1][j-1][t-1][1]  （新开一段：A[i-1] 拿了，但它是第 t-1 段的尾，第 t 段从 A[i] 另起）
```

一条一条拆：

| 来源 | 对应状态 | 发生了什么 |
|---|---|---|
| `[t][1]` 延续 | A[i-1] 是第 t 段的尾 | A[i] **续写**第 t 段，段数不变 |
| `[t-1][0]` 新开 | A[i-1] 没拿 | A[i] **新开**第 t 段（前面没东西碍事） |
| `[t-1][1]` 新开 | A[i-1] 拿了但属于第 t-1 段 | 第 t-1 段在 A[i-1] 处**封口**，A[i] **新开**第 t 段 |

> 三个来源 = "续一段" + 两种"新开一段"。**段数**要么不变（续）、要么 +1（新开）；**j** 永远 -1（A[i] 匹配掉了 B[j]）。

### 3.3 为什么 0/1 状态能防"重复计数"

如果只有 `[0/1]` 之外还按"A[i] 属于第几段"细分，就会把**同一段选法**按不同封口位置算多次。

0/1 只用"最后一个字符拿没拿"区分，每种选法**唯一确定**：看 A[i] 是否拿，拿的话它必是第 t 段的尾 → 不重不漏。

## 四、你踩的坑①：`f[i][j][t][0]` 不能放进 if 里（必考细节）

**错误写法**（第一版就是这里错的）：

```cpp
if (A[i-1]==B[j-1]) {
    f[nxt][j][t][1] = ...;
    f[nxt][j][t][0] = f[now][j][t][1]+f[now][j][t][0];  // ❌ 放进 if 里
} else {
    f[nxt][j][t][0] = 0;                                 // ❌ 还清零
}
```

**为什么错**：`f[..][0]` 描述的是"A[i] 不拿"。不拿 = A[i] 根本不参与匹配，**它跟 B[j] 等不等号有什么关系？** 没有。

- 放进 if → 只有 `A[i]==B[j]` 时才更新，其他时候 `f[..][0]` 还是上一次的脏数据或 0；
- 加 else 清零 → 更糟，直接抹掉了"跳过不匹配字符"的方案。

**正确写法**：`[0]` 转移放在 if 外面，无条件执行：

```cpp
if (A[i-1]==B[j-1]) {
    f[nxt][j][t][1] = ...;   // 只有这里需要判相等
}
f[nxt][j][t][0] = f[now][j][t][1]+f[now][j][t][0];  // ✅ 无条件
```

> 记忆点：**判不判字符相等，只跟"选没选"有关；"不选"永远不需要判相等。**

## 五、滚动数组（滚动抽屉）

### 5.1 为什么能滚

看转移：`f[i][...]` 只用到 `f[i-1][...]`——**只依赖上一层**。更早的层这辈子用不到了。

所以不用存整个 `f[n+1][m+1][k+1][2]`，只要**两个抽屉**轮流当"当前层"和"上一层"：

```
f[2][205][205][2]
```
（第一个 `2` = 两个抽屉，第二个 `2` = 0/1 状态。）

### 5.2 滚动流程

```cpp
int now=0, nxt=1;
f[now][0][0][0]=1;                 // 种子：空串，0 段，A[0] 没拿 → 1 种（什么都不干）

for (int i=1; i<=n; i++) {         // 依次“打开第 i 个字符”
    memset(f[nxt],0,sizeof(f[nxt]));   // 先清空新抽屉
    f[nxt][0][0][0]=1;                 // 重新播种：A[i] 一个都不拿，也形成“空状态”的 1 种
    for (int j=1; j<=m; j++)
        for (int t=1; t<=k; t++) {
            if (A[i-1]==B[j-1])
                f[nxt][j][t][1] = ...;
            f[nxt][j][t][0] = ...;
        }
    swap(now,nxt);                 // 抽屉对调：nxt 变 now，下一轮用另一个
}
```

解释每步：

1. **`memset(f[nxt],0,...)`**：新抽屉装的是"第 i 层的临时值"，先把旧数据（第 i-2 层的）清掉，防止残留污染。
2. **`f[nxt][0][0][0]=1` 重新播种**：遍历到 A[i] 时，"一个都不选"的方案永远有 1 种（空拼）。这就是种子传播——`f[i][0][0][0]` 对所有 i 都保持 1。
3. **`swap(now,nxt)`**：一层算完，新旧抽屉互换，下一轮继续。这就是"滚动"。

### 5.3 循环为什么从 1 开始

- 字符下标 `A[i-1]` / `B[j-1]`：因为 string 从 0 开始，DP 状态里的 i、j 是"长度/前几个"，是 **1-index 语义**。
- `j=0`、`t=0` 的**边界状态不需要进循环算**：
  - `j=0`：B 一个都没拼，A 随便跳，只有 `f[..][0][0][0]=1` 一种，其余全是 0（用 memset + 种子搞定）；
  - `t=0`：用了 0 段，只有 `[0]` 状态非零，`[1]`（用了 0 段还说 A[i] 服役）不存在，天然是 0。
- 但转移里 `j=1` 时会读 `f[now][0][...]`，`t=1` 时会读 `f[now][..][0]` → **边界值恰好被读**，所以必须用种子/memset 把边界先放对。

> 一句话：**边界不"算"，靠"种子+memset"喂；转移靠边界喂**。忘了种子的传播，答案是 0。

## 六、你踩的坑②：三数相加爆 int（隐蔽的大数据坑）

```cpp
f[now][j-1][t-1][1] + f[now][j-1][t][1] + f[now][j-1][t-1][0]
```

- 每个 `f` 值都是 `%MOD` 后的，最大 **MOD-1 ≈ 1e9**；
- 三个相加最大 **≈ 3e9**；
- **int 上限 ≈ 2.1e9 → 爆了，有符号溢出是未定义行为**，答案随机错。

**为什么小数据测不出来**：样例、小测试的值都很小，加不出 3e9，永远不会触发。只有 n=1000、m=k=200 这种大数据、满状态堆积时才会炸。实测对比：

```
1000 200 50:  int=40128290   long long=985563232  ← int 版错
1000 200 100: int=???        long long=???        ← 也不一致
```

**两种修法（这题都行）**：

| 修法 | 写法 | 内存 |
|---|---|---|
| A. 数组开 long long | `long long f[2][205][205][2]` | 1.3MB（翻倍，仍小） |
| B. 表达式里强转 | `((long long)f[now][...]+f[now][...]+f[now][...])%MOD` | 0.66MB（省） |

> **关键区别：存储 vs 计算。**
> - **存储**：数组里的值永远 ≤ MOD-1 ≈ 1e9，**int 装得下**，存用 int 足够；
> - **计算**：**加法的过程**会临时超过 int → 必须用 long long。
> 所以 B 写法"存用 int、算用 long long"最省内存。这题能滚动、只有两抽屉，A 的 1.3MB 也无所谓；但**不能滚动的题**（全量 `f[n+1][m+1][k+1][2]`），A 会把 324MB 变 648MB → MLE。**养成"存用 int、算 cast long long"的习惯。**

## 七、完整代码（滚动 + long long 数组版，已验证）

```cpp
#include<bits/stdc++.h>
using namespace std;
const long long MOD=1000000007;
string A,B;
long long f[2][205][205][2];   // [抽屉][j][t][0/1]，0=没拿A[i]，1=拿了(是第t段的尾)
int n,m,k;
int main(){
    cin>>n>>m>>k;
    cin>>A>>B;
    int now=0,nxt=1;
    f[now][0][0][0]=1;                    // 种子：空拼=1种
    for(int i=1;i<=n;i++){
        memset(f[nxt],0,sizeof(f[nxt]));  // 清空新抽屉
        f[nxt][0][0][0]=1;                // 重新播种
        for(int j=1;j<=m;j++){
            for(int t=1;t<=k;t++){
                if(A[i-1]==B[j-1]){       // 只有"选"才需要字符相等
                    f[nxt][j][t][1]=(f[now][j-1][t-1][1]+f[now][j-1][t][1]+f[now][j-1][t-1][0])%MOD;
                }
                f[nxt][j][t][0]=(f[now][j][t][1]+f[now][j][t][0])%MOD;  // "不选"无条件算
            }
        }
        swap(now,nxt);
    }
    cout<<(f[now][m][k][0]+f[now][m][k][1])%MOD;
    return 0;
}
```

## 八、复杂度

| | 时间 | 空间 |
|---|---|---|
| 总量 | O(n·m·k) | O(m·k)（滚动后） |

n=1000、m=k=200 → 4×10⁷，-O2 下稳过。不滚动是 O(n·m·k) 内存 → 会爆，所以**滚动数组不是优化，是刚需**。

## 九、知识点小结

> **多维 DP 的"拿/不拿"维度**：当转移需要区分"字符是延续上一段，还是新开一段"，就加一维 0/1 记录状态（像 01 背包的选/不选）。
>
> **三道教训**：
> 1. "不选"的转移**无条件**执行，别让字符相等判断干扰它；
> 2. 三个 ~1e9 相加会爆 int，**存储用 int、计算 cast long long**；
> 3. 边界（j=0、t=0）**靠种子+memset 喂**，不靠循环算，但转移会读它 → 顺序要对。
