# P5937 [CEOI1999] Parity Game 奇偶游戏 题解

> 洛谷 P5937 | 难度：蓝 | 知识点：带权并查集（模 2 异或）+ 离散化 + 前缀和

---

## 一、题目模型

裁判心里有一串 0/1（长度可达 1e9）。它会依次给出 `l r even/odd`，表示区间 `[l,r]` 里 1 的个数是偶数还是奇数。按顺序往下读，**直到某句话与前面所有话矛盾为止**。

**输出**：
- 矛盾发生在第 i 句话 → 输出 **i−1**（前 i−1 句都可信）
- m 句话全不矛盾 → 输出 **m**

---

## 二、核心转化：区间奇偶 → 点对关系（最隐蔽的一步）

定义**前缀奇偶**：

```
S[i] = 前 i 个数里 1 的个数的奇偶（模 2）
```

区间 `[l,r]` 里 1 的个数 = 前 r 个 − 前 l−1 个，模 2 下减法就是异或：

```
区间 [l,r] 的 1 的个数奇偶 = S[r] ⊕ S[l-1]
```

于是每条语句变成 **S[l−1] 和 S[r] 两个点之间的关系**：

| 语句 | S[l−1] 与 S[r] 的关系 | parity 值 |
|------|----------------------|-----------|
| even（偶数个 1） | 相同 | 0 |
| odd（奇数个 1）  | 不同 | 1 |

**区间问题变成了点对问题**：一堆点，不断被告知"某两点相同/不同"，问第几句开始矛盾。

> **到这里才轮到并查集。** 上面这一步（前缀和）是整题隐藏最深的地方，并查集反而是最后最简单的一步。

---

## 三、离散化：把 1e9 的坐标压成小编号（点名册）

`l−1`、`r` 最大 1e9，不可能开 1e9 的数组。但真正出现的点最多 `2m` 个（每次 2 个端点）。用 `unordered_map` 当**点名册**：每个第一次见到的坐标，发一个 1..k 的小编号，之后所有数组只跟小编号打交道。

```cpp
unordered_map<long long,int> mp;
int idx = 0;
int getid(long long x){
    if(!mp.count(x)) mp[x] = ++idx;   // 新面孔，发新编号
    return mp[x];                      // 老面孔，报出已有编号
}
```

数组大小只开 `2m` 级别，完全够用。

## 四、带权并查集（模 2 异或）

两个数组，两个含义：

| 数组 | 存什么 | 回答的问题 |
|------|--------|-----------|
| `fa[x]` | x 的**直接上司**是谁 | 我在哪个组？（关系链怎么走） |
| `d[x]`  | 我和上司是**什么关系** | 0=相同 / 1=不同 |

普通并查集只有 fa（只要"谁和谁一组"）；带权并查集多了 d（还要组内关系），这就是"带权"两个字。

### find：必须"先递归、再升级、最后换上司"

```cpp
int find(int x){
    if(fa[x] != x){
        int root = find(fa[x]);  // 1. 上司先爬到根（返回时 d[fa[x]] 已是"上司→根"）
        d[x] ^= d[fa[x]];        // 2. "我→上司" ⊕ "上司→根" = "我→根"
        fa[x] = root;            // 3. 最后才压缩，换上根做上司
    }
    return fa[x];
}
```

**为什么顺序不能乱**：`d[x]` 存的是和"旧上司"的关系。压缩后上司换成根，若 d[x] 不同步升级，就成了**"半截关系"**——`fa[x]` 指向根、`d[x]` 却描述旧上司，后面 `d[u]^d[v]` 的判断全是垃圾。

顺序反了会怎样？先 `fa[x]=find(fa[x])` 再 `d[x]^=d[fa[x]]`：此时 `d[fa[x]]` 读的是 `d[root]=0`（根和自己当然是相同），异或 0 等于**啥也没干**，关系直接丢失。

### merge 与矛盾判断

```cpp
// 不同根：把 u、v 挂进同一棵树，凑出关系 parity
int ru = find(u), rv = find(v);
if(ru == rv){
    // 同根：验证已有关系是否一致
    if((d[u] ^ d[v]) != parity) → 矛盾
} else {
    fa[ru] = rv;
    d[ru] = d[u] ^ d[v] ^ parity;   // 反解：d[ru] 该取何值，才能让 u、v 关系恰为 parity
}
```

## 五、完整 AC 代码

```cpp
#include<bits/stdc++.h>
using namespace std;
unordered_map<long long ,int>mp;
int ind=0;
vector<int>fa,d;
int getindex(long long  x){
    if(mp.count(x)==0){ mp[x]=++ind; }
    return mp[x];
}
int find(int x){
    if(fa[x]!=x){
        int root=find(fa[x]);
        d[x]^=d[fa[x]];    // 关键：先升级关系，再压缩
        fa[x]=root;
    }
    return fa[x];
}
int main(){
    long long n;
    int m;cin>>n>>m;
    fa.resize(2*m+4);
    d.resize(2*m+4);
    for(int i=1;i<=2*m+3;i++){ fa[i]=i;d[i]=0; }
    for(int i=1;i<=m;i++){
        long long l,r; string str;
        cin>>l>>r>>str;
        int u=getindex(l-1);
        int v=getindex(r);
        int parity=(str=="odd");   // even→0 相同，odd→1 不同
        int ru=find(u),rv=find(v);
        if(ru==rv){
            if((d[u]^d[v])!=parity){ cout<<i-1;return 0; }
        } else {
            fa[ru]=rv;
            d[ru]=d[u]^d[v]^parity;
        }
    }
    cout<<m;
    return 0;
}
```

## 六、踩过的坑（亲测）

1. **parity 写反**：写成了 `(str=="even")`。even 应该是 0（相同）、odd 应该是 1（不同）。样例输出会变成 5（正确是 3）。
2. **find 漏掉 `d[x]^=d[fa[x]]`**：只写了 `fa[x]=find(fa[x])`，d[x] 留在"半截关系"。样例输出同样是 5。**两个 bug 症状一样，只修一个都不行**——必须同时修对。
3. **输出**：矛盾在第 i 句 → 输出 `i-1`，不是 i；全对 → 输出 m。`return 0` 别忘了。

## 七、怎么想到并查集（判别法）

**集合/关系题的三条信号**：

1. 每条语句都在说**两个东西**之间的**关系**（同/不同）
2. 关系能**传递**：A~B、B~C 能推出 A~C
3. 边输入边**合并 / 查询 / 查矛盾**

套到本题：前缀和把区间变成点对 → "两个点的相同/不同关系 + 可传递 + 查矛盾" → **带权并查集**。

```
区间奇偶  →  前缀和  →  点对关系  →  带权并查集（模2异或）
                    ↑
              最隐蔽的跨越
```

**判别分水岭**：题目问"谁和谁"（分组/关系）→ 并查集；题目问"最大/最小是多少"（且答案能猜、能验证、随答案单调）→ 二分。（对比 P2440 木材加工：问一个数最大多少 → 二分。）

## 八、自测用例

**官方样例**（答案 3，第 4 句矛盾）：

```
10 5
1 2 even
3 4 odd
5 6 even
1 6 even
7 10 odd
```

**全对**（答案 2）：

```
10 2
1 2 even
2 3 odd
```

**第二句就矛盾**（答案 1）：

```
10 2
1 2 odd
1 2 even
```

**链式推导矛盾**（答案 2，需要沿链条推出 S0≠S4 才能发现第 3 句矛盾——这正是带权并查集比扩展域强的地方）：

```
10 3
1 3 odd
3 5 odd
1 5 even
```

> 推导：`1 3 odd` → S0≠S2；`3 5 odd` → S2≠S4；故 S0≠S4。而 `1 5 even` 要求 S0=S4 → 矛盾在第 3 句，输出 2。
