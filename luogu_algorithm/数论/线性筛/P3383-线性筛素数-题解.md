# P3383 【模板】线性筛素数

> 知识点：素数筛法（埃氏筛 → 欧拉筛/线性筛） / 难度：普及

## 一、题面（注意！现在的 P3383 改版了）

给定范围 n（≤10⁸）和 q 次询问，**每次询问第 k 小的质数是多少**。

```
输入: 100 5
      1
      2
      3
      4
      5
输出: 2
      3
      5
      7
      11
```

⚠️ 旧版 P3383 是"判断 x 是不是质数"，**新版改成了求第 k 小质数**。一开始按"输出 Yes/No"写会栽在题意上。

## 二、三层递进：为什么最终用线性筛

### 第 1 层 朴素试除法 —— 直接炸

对每次询问 x，暴力试除 √x 次。

- q 次 × √n 次 = 10⁶ × 10⁴ = **10¹⁰（100 亿）**，超时。

**本质**：每个询问都重新算一遍，没利用"上一次算出的信息"。

### 第 2 层 埃氏筛（埃拉托斯特尼）—— 空间换时间

先把 2~n 的质数一次性筛出来，之后每个询问 O(1) 查表。

```cpp
for(int i=2;i<=n;i++){
    if(isPrime[i]){                      // 只有质数 i 才去划倍数
        primes.push_back(i);
        for(int j=i*i;j<=n;j+=i)         // 从 i*i 开始划
            isPrime[j]=false;
    }
}
```

**为什么从 i×i 开始划？** i 的倍数 i×2, i×3, …, i×(i-1) 早就被更小的质数划掉了（比如 2×k、3×k），从 i×i 开始才轮到 i 出手。

**缺点**：同一个合数被划多次。12 = 2×6 = 3×4，i=2 时划一次、i=3 时又划一次。n=10⁸ 时重复标记很多，常数偏大。

### 第 3 层 线性筛（欧拉筛）—— 每个合数只划一次

**核心思想：每个合数恰好被它的"最小质因数"标记一次。** 全程 O(n)，每个合数只被标一次，没有重复。

```cpp
for(int i=2;i<=n;i++){
    if(isPrime[i])
        primes.push_back(i);               // ① 质数就入表（只干这一件事）

    for(int j=0;j<primes.size()&&i<=n/primes[j];j++){
        isPrime[primes[j]*i]=false;        // ② 每个 i 都拿质数表去划
        if(i%primes[j]==0)break;           // ③ 刹车（见下）
    }
}
```

**和埃氏筛的结构差异（最容易写错）**：
- 埃氏筛：**只有质数 i** 才进循环划倍数，内层循环套在 `if` 里；
- 线性筛：**每个 i（质数或合数）** 都拿质数表乘一遍划倍数，`if(isPrime[i])` 里**只做 push_back**，内层循环是 if 的**兄弟**（在 if 外面）。

**刹车规则 `if(i%primes[j]==0)break;`** —— 为什么一整除就停？

反证：设 p = primes[j] 能整除 i，即 i = p·m。那 i×primes[j+1] = p·m·primes[j+1]，它的**最小质因数是 p**，将来在 i' = m·primes[j+1]（比 i 小）那轮会由 p 把它标掉。现在标就重复了。刹车保证：**合数只被标一次**。

**拿例子验证（自己走一遍）**：

| i | 划掉 | 为什么停 |
|---|---|---|
| 8（合数照样跑！） | 8×2=16 | 8%2==0 → break，8×3=24 不在这标 |
| 12 | 12×2=24（24 的最小质因数=2 ✓） | 12%2==0 → break |
| 9 | 9×2=18，9×3=27 | 9%3==0 → break |

24 不是被 8×3 标的，而是被 **12×2** 标的——正好是它的最小质因数。每个合数一生只被划一次。

## 三、本 session 踩的两个坑

### 坑 1：`i*primes[j]<=n` int 溢出（隐藏 bug）

i 和 primes[j] 都能到 10⁸，乘积 **10¹⁶ 溢出 int**（上限 2.1×10⁹），回绕成负数后 `<= n` 恒成立，循环失控 / UB。

**改法（标准姿势）**：把乘法比较换成除法比较——

```cpp
i <= n/primes[j]      // 两个数都不超 n，除法不会溢出
```

### 坑 2：变量名接不上

`cin>>n>>p;` 读进 p，后面 `while(q--)` 用的却是从未赋值的 q → 垃圾值。**读入的变量名要和使用的完全一致**。

## 四、内存账：为什么用 vector\<bool\> 而不是 bool 数组

n=10⁸ 的 `bool isPrime[100000001]` 占 **100MB**，超内存。`vector<bool>` 是**位压缩**的：每个元素只占 1 位 → 10⁸ 个只占 **12.5MB**。加上质数表（10⁸ 以内约 576 万个 × 8B ≈ 46MB），总量 ~60MB，在 P3383 的 125MB 限制内。

## 五、怎么回答"第 k 小质数"

线性筛按 i 从小到大跑，**每发现一个质数就按升序 push_back**，所以 `primes` 天然有序：

```cpp
while(q--){
    int x; cin>>x;
    cout<<primes[x-1]<<"\n";    // 第 x 小的质数
}
```

第 k 小 → 下标 k-1。答案已自动排好序，白赚一个数据结构。

## 六、验证

- 样例 `100 5 / 1 2 3 4 5` → `2 3 5 7 11` ✓
- **洛谷 AC**（评测即最强验证）

## 七、思维总结

1. **空间换时间**：询问太多（10⁶）就预计算（一次筛完），查询 O(1)；
2. **筛法的进化**：朴素（每问重算）→ 埃氏筛（只质数划，有重复）→ 线性筛（人人划，刹车去重，O(n)）。优化的方向是**消灭重复劳动**；
3. **刹车规则是数学保证**：`i%primes[j]==0` 一停，就保证合数只会被最小质因数标到——想通"为什么停"比背代码重要；
4. **同样的坑**：溢出用除法比较、变量名自洽——这两条已经是你第 3 次踩了（P1873、P2679、P3383），该刻进肌肉记忆了。
