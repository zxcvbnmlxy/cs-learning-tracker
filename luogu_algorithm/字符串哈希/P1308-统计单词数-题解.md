# P1308 [NOIP2011 普及组] 统计单词数

> 知识点：字符串模拟——完整单词匹配 / 难度：普及-

## 一、题面

第一行一个单词 word，第二行一段文章（**含空格、含大小写**）。求 word 在文章中**作为完整单词**出现的次数，以及**第一次出现的位置**（下标从 0 开始）。没出现输出 `-1`。

```
输入:  To
      to be or not to be is a question
输出:  2 0        (To 出现2次: 位置0 和 13, 第一次位置0)
```

## 二、三个坑

| 坑 | 后果 | 正解 |
|---|---|---|
| 大小写不敏感 | "To" 匹配不上 "to" | 两串统一转小写 `tolower` |
| 文章含空格 | `cin>>s` 读不下 | 文章用 `getline`（cin 后残留换行要处理）|
| 必须"完整单词" | "pot" 里的 "to" 被误判 | **前后必须是空格或边界** |

## 三、核心绝招：首尾加空格大法

"完整单词"最难处理的是**文章开头/结尾**——那里没有空格，边界判断要特判。干脆**主动把边界变成空格**：

```
word    = " " + word + " "      →   " to "
article = " " + article + " "   →   首尾也补上空格
```

补完，不管单词出现在开头、中间还是结尾，**它两侧都必有空格**。于是判断"完整单词"退化成在 article 里找 `" to "` 这个完整块，`substr` 逐位置比即可。

## 四、一个容易踩的误区：位置要不要减 1？

**不用减，匹配位置 p 就是真实位置**。推导：

```
P = " " + A + " "      A 从 P[1] 开始
匹配 " to " 在 P 的 p 处 → 单词占 P[p+1 .. p+L] → 真实位置 = (p+1) - 1 = p ✓
```

开头加的空格把位置 +1，但匹配块**末尾还有一个空格**又抵消了 +1——正好 p == 真实位置。这跟直觉相反（以为补了空格会偏移），亲手走一遍 `"abc to"` 就明白：

```
A = "abc to",  P = " abc to "
P 里匹配 " to " 在 p=4 → A 里 "to" 真实位置也是 4 ✓
```

## 五、另一个坑：循环上界 `<=`

子串长度 len，最后一个合法起点是 `article.size()-len`：

```cpp
for(int i=0; i<=(int)article.size()-len; i++)   // 必须 <=, 不是 <
```

写 `<` 会漏掉文章**末尾**的单词——`to` / `abc to` 会输出 `-1` 而不是 `1 4`。这是最容易漏的一类 off-by-one。

## 六、代码

```cpp
string turn(string &s){   // 转小写 + 补空格, 返回新串
    for(char &c:s)
        if(c>='A'&&c<='Z') c=c-'A'+'a';
    return " "+s+" ";
}
int main(){
    string word, article;
    getline(cin, word);   word=turn(word);
    getline(cin, article); article=turn(article);
    int len=word.size();
    int first=(int)article.size()-len;   // 初始为最后合法位置, min 更新成第一次
    int cnt=0;
    for(int i=0;i<=(int)article.size()-len;i++)
        if(article.substr(i,len)==word){ cnt++; first=min(first,i); }
    if(cnt==0) cout<<-1<<"\n";
    else cout<<cnt<<" "<<first<<"\n";
}
```

**注意 `turn` 返回的是新串，调用处必须 `word=turn(word)` 接住**——不接住补的空格就白补了（本 session 踩的坑）。

## 七、验证（对拍）

- 样例 `To` + `to be or not to be is a question` → `2 0` ✓
- 对拍 **5000 组全过**：随机单词 + 随机文章（空格分隔、1/3 概率放入目标词），补空格法 vs 手工扫描单词边界法，计数与首次位置逐组一致。

## 八、思维总结 & 关联

1. **边界问题的通用解法**：与其特判开头/结尾，不如**把边界也变成统一形态**（补空格/哨兵字符）——判断逻辑只剩一种；
2. **`turn` 混用副作用和返回值**：转小写靠引用生效，补空格靠返回值——一个函数两个通道，调用处容易漏接。要么纯原地、要么纯返回，别混；
3. **off-by-one 的自觉**：`<` vs `<=`，用"最后一个合法起点"这句话在心里算一遍再写。
