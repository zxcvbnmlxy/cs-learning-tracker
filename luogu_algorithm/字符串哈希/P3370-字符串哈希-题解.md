# P3370 【模板】字符串哈希

> 知识点：字符串哈希（b 进制指纹 + 自然溢出） / 难度：普及+

## 一、题面

给 n 个字符串（n ≤ 10⁴，每串 ≤ 1500），问一共有多少个**不同**的串。

```
输入: 5           输出: 3
abc              (abc 出现3次算1个, bcd 1个, abcd 1个)
abc
bcd
abcd
abc
```

## 二、为什么用哈希

判断两个串相等要逐字符比 O(L)。朴素两两比 O(n²·L) = 10⁸×1500 直接炸；排序后比相邻 O(n log n · L) 勉强。

**哈希 = 给每个串算一个"身份号"整数**，比较两个串 = 比较两个数 O(1)。

> 和离散化同源：大而复杂的东西映射成一个整数。离散化映射到"排名"，哈希映射到"指纹"。

## 三、核心思想：字符串 = b 进制大数

把字符当数字位，从头滚到尾：

```
hash = hash × b + c        (c 是字符值, 比如 ASCII)
```

手算十进制同理：`abcd = ((a×10+b)×10+c)×10+d`，只是基数换成 b。

"ab"（a=97, b=98），base 131：`hash = 97×131 + 98 = 12805`。

**为什么不同长度的串不会撞号**：短串的 hash 永远 < b×最大字符，够不到长串的最小值，天然分开。

## 四、base 为什么必须是「> 字符集」的奇数

这是本 session 踩坑踩出来的核心经验，三个版本递进：

| 版本 | 式子 | 真实 base | 结果 |
|---|---|---|---|
| ① base 2 | `hash += hash + c` | 2 | 字符值 97~122 全 > 2，"数字位"溢出滚进相邻位，位置互相污染 → `"ba"=293="ac"` 确定性碰撞 |
| ② base 132 | `hash += hash*131 + c` | **132**（`+=` 把旧 hash 又加一遍！`hash+hash*131 = hash*132`） | 132 是偶数，`132^32 = 2^64·33^32 ≡ 0 (mod 2^64)` → 离末尾 >32 位的字符**全部消失** |
| ③ base 131 ✓ | `hash = hash*131 + c` | 131 | 131 > 128（字符装得下，不进位污染）；奇数（`131^k` mod 2^64 永不归零，一位都不消失）|

两条铁律：
1. **`=` 不是 `+=`**：滚动哈希每一步必须是 `hash = hash*b + c`，写 `+=` 会把 base 悄悄变成 b+1（甚至 b 本身有进位歧义）；
2. **base 是奇数且 > 字符集**（131 / 13331）：偶数在自然溢出下，幂次超过某阈值就整段归零（base 2 → 64 位、base 132 → 32 位），前缀全丢。

## 五、取模方式

| 方式 | 做法 | 特点 |
|---|---|---|
| **自然溢出** | `unsigned long long` 自动溢出，等价 mod 2⁶⁴ | 最快，竞赛最常用 |
| 大质数 | 全程 `% 1e9+7` | 手动防溢出，慢，但完全无争议 |

## 六、冲突

两个不同串可能算出同一哈希——自然溢出碰撞概率 ≈ 1/2⁶⁴，竞赛默认接受。**哈希值相等就当串相等**。

## 七、复杂度

每串 O(L)，共 O(总字符数) = 1.5×10⁷；set 插入 O(log n)。轻松过。

## 八、验证（对拍）

- 样例 `5 + {abc×3, bcd, abcd}` → `3` ✓
- 对拍 **2000 组全过**：随机 n≤100、串长 0~1500（真实上限）、字符集 62（a-z/A-Z/0-9，扩大碰撞面）、强制制造重复，`set<string>` 暴力 vs base-131 哈希去重，计数逐组一致。

## 九、思维总结 & 预告

1. **哈希 = 压缩**：把不可比/难比的东西压成整数再比，代价是理论上的碰撞概率；
2. **base 选型三件套**：> 字符集、奇数、自然溢出（131/13331 无脑用）；
3. **滚动哈希是基础版**：只给整串一个指纹。**前缀哈希**（预计算每个前缀的 hash，能 O(1) 取任意子串的 hash）才是字符串哈希的主力形态，下一题 P1308 和区间/回文类问题都靠它。
