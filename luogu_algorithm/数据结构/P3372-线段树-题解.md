# P3372 线段树 1 题解（线段树 + 懒标记 lazy 教程）

> 2026-08-24 完成 | 线段树第三档（build + query + lazy）全手写 | 本地对拍 1000 组通过
> 一句话定位：**给数组做区间加、区间求和。暴力 O(N) 一次，线段树 O(log N) 一次——代价是要处理「懒标记」这笔账。**

---

## 〇、题面

- `n` 个数，`m` 次操作。
- 操作 1：`1 x y k` → 区间 `[x,y]` 每个数 `+k`。
- 操作 2：`2 x y` → 查询区间 `[x,y]` 的和。
- 数据范围：`n,m ≤ 1e5`，元素和 `≤ 1e14` → **和用 long long**。

---

## 一、为什么暴力不行 → 撞上 O(N) 每次

直接想：区间加就是 `for(i=x;i<=y;i++) a[i]+=k`，区间查就是 `for` 累加。

- 一次操作 O(N)，`m=1e5`、`n=1e5` → **1e10**，跑不完。
- 前面学的树状数组只能做「单点改 + 区间查」或「区间改 + 单点查」，**区间改 + 区间查**这第三档需要两棵树（差分 + 另一棵），或者直接上**线段树**。

> 树状数组第三档 = 线段树的地盘。这一题就是它。

---

## 二、线段树三件套（上一课已建好的骨架）

每棵子树是一个节点，覆盖区间 `[l,r]`：

```
        [1,5]
      /      \
   [1,3]    [4,5]
   /   \    /   \
 [1,2][3,3][4,4][5,5]
```

- **根 = 1**，左孩子 `node*2`，右孩子 `node*2+1`，数组开 `4N`。
- 每个函数都长这样：`f(node, l, r, ...)`——**三件套**。
- 叶子：`tree[node].data = a[l]`；内部：`tree[node*2].data + tree[node*2+1].data`。
- 每个操作三种命运：**整块拿走 / 完全无关 / 劈两半**。

---

## 三、lazy 标记：把「更新」拆成两步

### 问题：没有 lazy 的区间改

`update [2,4] +k` 要一路劈到底，把 `[2,2][3,3][4,4]` 三个叶子都改掉，再一路回溯——**O(N log N)**，还是慢。

### 懒的核心观察

`update [2,4] +k` 劈到 `[3,4]` 时，**这个节点整个被覆盖**。既然它整块都要 +k，那我能不能只改它一个点，先不动它下面的叶子？

→ 能。这就是**记账**：

```
tree[node].data += k × (r-l+1)   // 我自己的和先改对(整个区间都+k, 共 len 个元素)
tree[node].lazy += k              // 挂一笔账:下面每个元素还欠 +k
return                             // 子孙一个都不碰,直接走人
```

### 记账 vs 兑现

- **记账（立即）**：整块覆盖的节点当场 `data += k×len`、挂 `lazy`。它自己的和立刻正确。
- **兑现（推迟）**：它下面的子孙**没改**，只挂了个标记。等将来**某个操作要劈进这片区域**时，再把账还了。

> 一句话：**能懒就懒——整块覆盖就记账走人，只有必须往深处走才还账。**

### 那 lazy 什么时候「还」？→ 下潜时

要往下劈（无论 update 还是 query）之前，如果当前节点挂着账，**必须先把账还给两个孩子**，否则孩子读出来是旧值。这个动作叫 **pushDown**：

```
pushDown(node, l, r):
  mid = (l+r)/2
  tree[左孩子].data += lazy × (mid-l+1)   // 左孩子有 mid-l+1 个元素
  tree[右孩子].data += lazy × (r-mid)     // 右孩子有 r-mid 个元素
  tree[左孩子].lazy += lazy
  tree[右孩子].lazy += lazy
  tree[node].lazy = 0                      // 账还清了
```

**为什么签名必须有 `l,r`？**——没有区间长度，就算不出孩子该加 `lazy × 几个元素`。这是 lazy 唯一的新参数。

---

## 四、update：三件套里多一档「记账」

```
update(node, l, r, ql, qr, k):
  完全无关(qr<l 或 ql>r)     → return
  整块覆盖(ql≤l 且 qr≥r)     → 记账:data += k×(r-l+1); lazy += k; return
  劈两半                      → pushDown → 劈左 → 劈右 → 回来修自己 data
```

**和 query 的三个区别：**
1. 整块那档是**记账**（不是 `return data`）——`update` 是写操作，query 是读操作。
2. 劈之前必须 `pushDown`。
3. 递归回来要**重建自己**：`tree[node].data = tree[node*2].data + tree[node*2+1].data`——因为孩子改了，自己的和过期了。这是「下去改、回来修」。

---

## 五、query 也要 pushDown

query 只读，**但劈之前同样要还账**。比如之前 `update [1,5] +k` 只在根记账挂 lazy，现在 `query [2,3]` 要劈下去——根欠的账不还，孩子全是旧值。

> pushDown 的触发条件不是「update」也不是「query」，而是**「要往深处走」**。两个函数都得有。

---

## 六、复杂度

| | 时间 | 空间 |
|---|---|---|
| 每次操作 | **O(log N)** | O(4N) |

`n=1e5` → 1e5 × log ≈ **1.7e6**，秒过。区间改+区间查从 O(N) 降到 O(log N)，这就是 lazy 的价值。

---

## 七、你踩的坑（本课全记录）

1. **`node*2+!` 笔误**——`!` 打成 `1`，语法错。编译器逮得到。
2. **`ll` 忘声明**——`typedef long long ll;` 每份代码都要带。
3. **pushDown 传参错**——写成 `pushDown(node,l,mid)` 分两次调，等于在错误的区间长度上还账；要的是一次 `pushDown(node,l,r)`。
4. **递归孩子忘 `*2`**——`update(node,l,mid,...)` 写成父节点自己，永远走不深 → 逻辑乱。
5. **回溯修错对象**——该修 `tree[node]`（自己），不是 `node/2`（爸爸）。
6. **以为「更新只在 query 时发生」**——错。记账点自己当场更新；update 路径上的祖先回溯当场重建；深层兑现可能被下一个 update 触发。lazy 只是「推迟」，不是「取消」。
7. **整块那档 return 错位置**——记账完 return，不能继续往下劈。

## 八、线段树 + lazy 手写模板（背下来）

```cpp
struct Node{ ll data; int lazy; };  // 两棵空间:和 + 懒标记

void build(node, l, r)    // 叶子 data=a[l]; 内部 data=左右和
void pushDown(node, l, r) // 孩子 data += lazy×len; 孩子 lazy +=; 自己清0
void update(node, l, r, ql, qr, k)
  // 无关→return; 整块→data+=k×len,lazy+=k,return; 劈→pushDown→左→右→修自己
ll query(node, l, r, ql, qr)
  // 无关→0; 整块→data; 劈→pushDown→左+右
```

**记忆钩子：**
- 三件套 `(node,l,r)`，三种命运，两套下标（tree 按 node、a 按下标）。
- 能懒就懒：整块覆盖 → 记账走人。
- 要往深处走 → 先 pushDown 还账。
- 下去改、回来修（update 才有；query 只读不修）。
- 和用 `long long`，数组开 `4N`。
