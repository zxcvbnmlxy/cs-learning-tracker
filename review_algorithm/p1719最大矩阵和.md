
kadane最大连续子段和 + 压缩矩阵
行压缩

```cpp
#include<bits/stdc++.h>
using namespace std;
typedef long long ll;
int main(){
    int n;cin>>n;
    vector<vector<ll>>a(n+1,vector<ll>(n+1,0));
    vector<vector<ll>>pre(n+1,vector<ll>(n+1,0));
    for(int i=1;i<=n;i++){
        for(int j=1;j<=n;j++){
            cin>>a[i][j];
            pre[i][j]=a[i][j]+pre[i][j-1];
        }
    }
    ll ans=LLONG_MIN;vector<ll>row(n+1,0);
    for(int left=1;left<=n;left++){
        for(int right=left;right<=n;right++){
            row.assign(n+1,0);       
            ll mx=-1e8;
            for(int k=1;k<=n;k++){
                row[k]=pre[k][right]-pre[k][left]+a[k][left];
                mx=max(row[k],mx+row[k]);
                ans=max(mx,ans);
            }
            
        }
    }
    cout<<ans<<"\n";
    return 0;
}
```

## 踩坑记录（B 行前缀版，2026/09/10）

### 坑①：Kadane 的 best 放在了循环外 → 丢峰

错误写法（第一版）：
```cpp
ll mx=LLONG_MIN;
for(int k=1;k<=n;k++){
    row[k]=pre[k][right]-pre[k][left]+a[k][left];
    mx=max(row[k],mx+row[k]);   // 这是 cur：以当前行结尾的最大和
}
ans=max(mx,ans);                // ← best 在循环外取！
```
`mx=max(x,mx+x)` 算的是**以当前这一行为结尾**的最大子段和，遇到负的行会**往下掉**。
best 放循环外 → 只拿到“以最后一行为结尾”的那个值，**中途的峰丢了**。

反例 `rowW=[5,-10,1]`：真值 **5**，错解输出 **1**（第 1 步的 5 被后面覆盖）。
> 注意：这组在官方样例上**照样能过**——因为样例的最优子段恰好“以最后一行为结尾”，
> 是 bug① 唯一侥幸正确的情形。**样例过了 ≠ 对。**

正解（`mx` 专职当 cur，`ans` 专职当 best，**best 在循环内每步取**）：
```cpp
ll mx=-1e8;                     // cur
for(int k=1;k<=n;k++){
    row[k]=pre[k][right]-pre[k][left]+a[k][left];
    mx=max(row[k],mx+row[k]);   // cur 会起伏
    ans=max(mx,ans);            // ← best 在循环内！
}
```

### 坑②：inf 哨兵参与了加法 → 溢出

`ll mx=LLONG_MIN;` 后算 `mx+row[k]`，当 `row[k]` 为负时 `LLONG_MIN+负数` 是**有符号溢出（UB）**，
实际回绕成**巨大正数**，把 ans 污染了。官方样例实测输出 `9223372036854775805`。

修法：哨兵取任何 **≤0 且不会被加爆** 的值（如 `-1e8`）；或 `cur=0` 起步，天然规避。
> 一句话：**inf 别拿去加。**

### 这次的教训

- **样例过了 ≠ 对**：真正照出 bug① 的是 `[5,-10,1]` 这种“最优不在末尾”的边界数据。
- **写完必须跑，跑完必须对拍**：“我感觉就是这样” 写出来的代码，连官方样例都没过。
- 验证方式：对拍 2000 组随机数据（n≤6，值 -9..9，含全负）→ 全过才算真通。
