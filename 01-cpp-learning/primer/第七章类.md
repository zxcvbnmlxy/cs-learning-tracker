构造函数的任务是初始化对象的数据成员，只要类的对象被创建，就会执行构造函数
初始化不等同于赋值，构造函数里用初始化列表才是真正的初始化，在构造函数体内用=赋值，
即使对象没有定义构造函数，编译器会自动生成一个合成的默认构造函数，但是有三特殊情况，不再生成：1）若在累内我们定义了一个带参构造函数，2）含有内置类型或者复合类型成员的类应该在类的内部初始化这些成员（未初始化，内置类型存的都是垃圾值），或者定义一个自己的默认构造函数，只有这些成员全都被赋予了类内的初始值时，这个类才可以使用合成的默认构造函数3）若类内包含其他类类型的成员并且这个成员的类型没有默认构造函数
在类外定义构造函数，比如Sales::Sales,就是我们定义类的成员，有成员名字和类名相同，所以是一个构造函数，但没有构造函数初始值列表，初始值列表是空的

访问控制与封装
定义在public说明符之后的成员在整个程序内可被访问，public成员定义类的接口，定于在private说明辅助后的成员可以被类成员函数访问但是不能被使用该类的代码访问，private部分封装了类的实现细节
class 和struct唯一区别就是默认的访问权限不同。struct 所有成员都是public，class是private
封装的优点：1 保护数据不被外部随意修改 2 修改内部实现不影响外部代码（只要接口不变，里面随便改，使用者不受影响），就是调用的地方不用修改

5. 类类型与声明，重点
即使两个类的成员列表长得一模一样，它们在C++里也是完全不同的类型。另外，类可以先声明不定义（这叫前向声明），在它定义之前，它是个不完全类型。
难点：不完全类型的使用限制很多。只能定义指向它的指针或引用，可以声明（但不能定义）以它为参数或返回类型的函数。因为编译器必须先知道完整的定义，才知道一个对象要占多大空间。一个经典的例子是，一个类里面不能放它自己类型的成员，但可以放指向它自身类型的指针或引用。
6. 友元类（Friend Classes）， 面试常考

3. 类内定义 vs 类外定义 + inline
· 类内定义：编译器自动把它当内联函数处理（你不需要写 inline）。
· 类外定义：必须显式加 inline 关键字。
· 你写的“编译器不一定会采纳”：正确，inline 只是请求，不是命令。
· 你写的“函数声明和定义不在同一个头文件，编译器会找不到定义展开”：正确，所以内联函数通常声明和定义都放头文件里。
4. 链式调用
你抓到了核心：返回 *this，返回调用该函数的对象的引用。给你一个具体例子：
class Screen {
public:
    Screen &move(int r, int c) { /* ... */ return *this; }
    Screen &set(char ch) { /* ... */ return *this; }
};
// 链式调用
myScreen.move(4, 0).set('#');
第一句 myScreen.move(4, 0) 返回的还是 myScreen 自己（的引用），所以能直接接 .set('#')。这就是 return *this 的效果。

6. 友元类
· 如果类 A 声明类 B 为友元，那么 B 的所有成员函数都可以访问 A 的私有和保护成员。
· 友元关系不能传递：A 是 B 的朋友，B 是 C 的朋友，A 和 C 之间没有特殊关系。
· 面试这么说：“友元类让另一个类的所有成员函数都能访问我的私有成员，但友元关系不能传递。”
7. 类的前向声明
· 前向声明就是只声明类名，不给出类的具体内容：class Screen;
· 这个状态下，Screen 叫不完全类型。
· 能做什么：定义指向它的指针或引用，声明（但不能定义）以它为参数或返回类型的函数。
· 不能做什么：创建对象、访问成员——编译器不知道对象多大、有什么成员。
· 面试这么说：“前向声明用来打破循环依赖，只能定义指针或引用，不能创建对象。”
8. 两个结构相同的类是否同类型
struct A { int x; }; 和 struct B { int x; }; 是完全不同的类型。不能用 A 的对象给 B 的对象赋值，除非显式写了类型转换。
面试这么说：“C++ 是强类型语言，类名就是类型标识，即使两个类的成员完全一样，它们也是不同的类型。”

7.4 类的作用域
重点1：普通代码必须在声明之后使用，但在类中可以先使用后声明，编译器是将整个类定义扫描一遍：
1 第一遍：处理所有成员定义（数据成员，成员函数的声明），不包括函数体
2 第二遍：在处理成员函数内使用的名字；
重点2： 类作用域嵌套（内外名字冲突）
如果再类外面定义成员函数，三层作用域：1成员函数内部局部变量，2类作用域 3全局作用域
查找顺序：从内到外，
